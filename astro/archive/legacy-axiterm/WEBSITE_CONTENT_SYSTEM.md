# Website Content System

This document defines how Axiterm website content should be written, expanded, measured, and improved. It is the operating standard for copy, evidence, information gain, internal links, downloads, and page lifecycle.

## 1. Content Mission

The website does not simply describe products. It helps buyers reduce procurement risk.

Every important page should help one or more roles:

- Engineer: fit, drawing, material, tolerance, current path, insulation, validation.
- Purchasing: MOQ, lead time, sample path, price assumptions, packaging, repeat order.
- Quality: inspection, sample approval, traceability, finish zones, defect controls.
- Owner / sourcing lead: factory credibility, long-term supplier fit, export communication.

## 2. Business Dashboard

Website performance should be measured as a business funnel, not only traffic or rankings.

Primary funnel:

```text
Traffic
-> Qualified RFQ
-> Engineering Review
-> Prototype / Sample
-> Sample Approval
-> Mass Production Order
-> Repeat Order
```

Core metrics:

| Stage | Metric |
| --- | --- |
| Traffic | Organic sessions, paid sessions, landing pages, source quality |
| Qualified RFQ | RFQs with drawing/sample, quantity, application, company email, project stage |
| Engineering Review | RFQs that receive technical review or follow-up questions |
| Prototype / Sample | Sample requests or first-article projects |
| Sample Approval | Approved sample or approved drawing / acceptance criteria |
| Order | First production order value and conversion rate |
| Repeat Order | Repeat orders, annual programs, or supplier-replacement wins |

Operating rule:

- Revenue > Orders > Samples > Qualified RFQs > Traffic.
- RFQ quality matters more than RFQ count.
- Pages should be evaluated by qualified RFQ contribution, not only visits.

## 3. Evidence Library

Use specific evidence categories instead of vague trust claims.

### Engineering Evidence

- Drawings or drawing-review checklist.
- Tolerance policy or tolerance decision notes.
- Material selection notes.
- Current path or contact-surface checks.
- Inspection checklist.
- Mating interface examples.
- Design notes.

### Manufacturing Evidence

- Machine categories.
- Process route.
- CNC turning / automatic lathe notes.
- Injection molding workflow.
- Plating preparation.
- Assembly sequence.
- QC process.
- Packaging process.

### Commercial Evidence

- MOQ is project-based.
- Lead time is confirmed after review.
- Sample path.
- Packaging options.
- Private label scope.
- Export communication.
- Repeat order assumptions.

### Project Evidence

- Reference sample review.
- Sample approval path.
- Drawing revision.
- Supplier replacement.
- Repeat-order control.
- Case study.
- Before / after design change.

Evidence rule:

- Do not invent numbers or certifications.
- If a value is not verified, write it as project-based or confirmed after review.
- Replace conceptual evidence with real assets when available.

## 4. Information Gain Standards

Information gain means the page provides useful knowledge competitors may not provide.

Preferred formats:

- Comparison.
- Selection guide.
- Failure risk.
- Tolerance table.
- Material guide.
- Inspection checklist.
- Design notes.
- RFQ example.
- Application fit table.
- Finish-zone explanation.
- Sample approval workflow.

Avoid:

- Generic "high quality" claims.
- Repeating the same company introduction.
- Long paragraphs without decision value.
- Consumer audiophile language that weakens OEM positioning.

## 5. Hero Copy Standard

Hero copy should answer three questions:

1. What is this page about?
2. Who is it for?
3. What should the buyer do next?

Good structure:

- Eyebrow: page category or buyer intent.
- H1: clear product/application/capability.
- Intro: product + application + review scope.
- CTA: RFQ or next step.

## 6. Quick Specs Standard

Quick Specs should help the buyer decide if the page fits their project.

Use when exact values are project-specific:

- "Defined by drawing."
- "Confirmed after application review."
- "Reviewed with mating hardware."
- "Sample approval where required."

Do not add unsupported fixed values.

Recommended rows:

- Typical use.
- Interface.
- Material route.
- Finish route.
- Insulation / assembly.
- RFQ basis.
- Validation or inspection basis.

## 7. FAQ Standard

FAQ should remove buying friction.

Product FAQ should answer:

- Can it be customized?
- What drawing/sample information is needed?
- What material or finish can be reviewed?
- What controls sample approval?
- What affects MOQ or lead time?
- Can logo, packaging, or private label be reviewed?

Application FAQ should answer:

- Does this fit my equipment?
- Which product family should I start with?
- What interface details matter?
- What risks should be defined before sample approval?

Capability FAQ should answer:

- What can be manufactured?
- What information is needed for review?
- What risks does this process control?
- What evidence supports repeat production?

## 8. CTA Standard

Use action language tied to buyer intent.

Preferred CTAs:

- Upload Drawing for RFQ.
- Send Drawing for Review.
- Request Manufacturing Review.
- Start a Binding Post RFQ.
- Request an Application-Based RFQ.
- Review Manufacturing Capability.

Avoid generic `Contact Us` as the primary CTA on high-intent pages.

CTA placement:

- Hero for S-level pages.
- Mid-page after fit or evidence section.
- End-page CTA.

## 9. Internal Link Standard

Each page should point to the next buyer step.

Product pages should link to related product family, relevant application, relevant capability, and RFQ.

Application pages should link to matching product family, relevant capability, and RFQ.

Capability pages should link to matching products, matching applications, and RFQ.

RFQ should link to FAQ, contact fallback, and thank-you next steps.

## 10. Image and Media Standard

Image priority:

1. Real product photos.
2. Real CNC / machining / inspection photos.
3. Real packaging / shipment / assembly photos.
4. Real sample or project photos.
5. Conceptual images as temporary placeholders.

When using conceptual images:

- Label them as conceptual.
- Do not imply they are actual factory or project evidence.

Future media to collect:

- Product close-ups.
- CNC machines.
- Thread inspection.
- Surface finish / plating.
- Injection molded insulation.
- Assembly.
- Packaging.
- Shipment.
- QC equipment.

## 11. Download Standard

Downloads should support engineering validation.

Future download types:

- Product datasheet.
- Drawing template.
- RFQ checklist PDF.
- Material guide.
- Plating guide.
- Packaging guide.
- Sample approval checklist.

If a download is not ready, use a `Send drawing for review` CTA instead of fake download links.

## 12. Content Lifecycle

Pages should improve in versions.

### V1: Fit + RFQ

- Clear page intent.
- Buyer fit.
- RFQ CTA.

### V2: Specs + FAQ

- Quick Specs.
- Buyer checklist.
- Product or application FAQ.

### V3: Evidence + Comparison

- Decision evidence.
- Material, finish, or process comparison.
- Failure risks.

### V4: Downloads + Media

- Datasheet or checklist.
- Real product or process visuals.
- Video or inspection images.

### V5: Case + Original Data

- Case study.
- Project evidence.
- Original tables or decision frameworks.
- Repeat order or sample approval story.

After S-level and A-level pages reach the procurement-decision standard, use `NEXT_PHASE_OPERATING_PLAN.md` to prioritize real evidence assets, Knowledge Base topics, and Google Ads validation instead of repeatedly rewriting page copy.

## 13. Competitive Benchmark Rule

Benchmarking should support execution, not delay it.

Use competitors to ask:

- What does an international industrial buyer expect on this page?
- What proof do TE, Molex, Phoenix Contact, LAPP, Amphenol, or similar sites provide?
- What can Axiterm explain more practically for OEM terminal component buyers?

Do not copy competitor language or structure directly.

## 14. Resource Layer Plan

Future `Engineering Resources` should be added after core S-level and A-level pages are stronger.

Recommended resource hubs:

- Material Guide.
- Tolerance Guide.
- Current Guide.
- Thread Guide.
- Surface Finish Guide.
- Packaging Guide.
- Inspection Guide.

Each resource should link back to products, applications, capabilities, and RFQ.

## 15. Page Completion Definition

A page is complete for the current phase when:

- Buyer role is clear.
- Page intent is clear.
- Fit judgment is possible.
- Procurement risk is reduced.
- Evidence is present.
- Information gain is present.
- CTA is clear.
- Next step is clear.
- Build passes.
- No encoding issues are introduced.
